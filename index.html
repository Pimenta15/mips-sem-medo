1.1O que é Assembly e o que é o MIPS

Assembly (linguagem de montagem) é o "binário escrito com palavras". Em vez de escrever 00000010001100100100000000100000, você escreve add $t0, $s1, $s2. Um programa chamado montador (assembler) traduz uma coisa na outra. Você pode dar nomes (labels) para posições da memória, como loop: ou fim:.

O MIPS é o conjunto de instruções que a disciplina usa. É do tipo RISC (instruções simples) e foi usado por NEC, Nintendo, Silicon Graphics e Sony. Assembly é mais primitivo que C: não tem for, while nem if prontos. Você monta tudo com desvios. Serve quando memória ou velocidade são críticas, ou para usar coisas do hardware que a linguagem de alto nível não mostra.

Os 4 princípios de projeto do MIPS (decore, cai em prova)

1. A simplicidade favorece a regularidade

Toda instrução aritmética tem exatamente 3 operandos. Sempre. Isso deixa o hardware simples.

2. Quanto menor, mais rápido

Por isso são só 32 registradores. Mais registradores deixariam o ciclo de clock maior e a máquina mais lenta.

3. Um bom projeto exige compromisso

Todas as instruções têm 32 bits, mas existem formatos diferentes (R, I e J) para caber tudo.

4. Torne o caso comum mais rápido

Constantes aparecem o tempo todo, então existe addi com a constante dentro da própria instrução.

Na Aula 7 aparece um 5º item: toda instrução MIPS escreve um único resultado, sempre no final da execução. Isso facilita o adiantamento no pipeline.

1.4Memória: endereço, base e deslocamento (de 4 em 4)

Os registradores são só 32. Tudo o que é grande, como um vetor de 1000 números, mora na memória. Para usar um valor da memória você precisa saber onde ele está, e esse "onde" é o endereço.

1º A memória é uma fileira de gavetas numeradas

Analogia

Imagine um armário com milhões de gavetas pequenas, uma ao lado da outra. Cada gaveta guarda 1 byte (8 bits) e tem um número: o endereço. Um número inteiro do MIPS (uma palavra) tem 32 bits, ou seja, 4 bytes, então ele ocupa 4 gavetas seguidas.

Num laço, o endereço muda a cada volta. Os slides usam os dois jeitos abaixo. Os dois andam 4 bytes por volta, só muda o que você guarda no registrador.

Analogia
Um label é uma placa no caminho (loop:, fim:). O beq/bne é um "se tal coisa, siga para a placa X". O j é "siga para a placa X, sem perguntar".

Um bloco básico é uma sequência de instruções sem desvio, a não ser talvez no fim, e sem labels, a não ser talvez no começo. Um for em MIPS é sempre o mesmo esqueleto:

switch / case com tabela de desvios (slides 27–28)

  
Para escolher entre muitos casos, o slide usa uma tabela de endereços na memória (JumpTable) e a instrução jr, que pula para o endereço guardado num registrador. $s5 = k, $t2 = 4, $t4 = início da tabela.

  
      slt $t3, $s5, $zero    # k < 0 ?
      bne $t3, $zero, Exit   # se sim, sai
      slt $t3, $s5, $t2      # k < 4 ?
      beq $t3, $zero, Exit   # se k >= 4, sai
      add $t1, $s5, $s5      # 2k
      add $t1, $t1, $t1      # 4k
      add $t1, $t1, $t4      # endereço de JumpTable[k]
      lw  $t0, 0($t1)        # t0 = JumpTable[k]
      jr  $t0                # pula para o caso certo
L0:   add $s0, $s3, $s4      # k=0: f = i + j
      j   Exit
L1:   add $s0, $s1, $s2      # k=1: f = g + h
      j   Exit
L2:   sub $s0, $s1, $s2      # k=2: f = g - h
      j   Exit
L3:   sub $s0, $s3, $s4      # k=3: f = i - j
Exit:

1.6Procedimentos (funções) e a pilha

  
Procedimento é a "função" do assembly: organiza o programa, facilita entender e permite reaproveitar código. Os parâmetros são a barreira entre o procedimento e o resto do programa. Os 6 passos de uma chamada (slides 29–30):

  

    1. Põe os parâmetros em $a0–$a3→
    2. Transfere o controle (jal)→
    3. Garante memória (pilha)→
    4. Faz a tarefa→
    5. Põe o resultado em $v0–$v1→
    6. Volta (jr $ra)
  

  
A pilha

  
    
    
  • Serve para guardar registradores na entrada do procedimento e devolver na saída (dá "mais registradores" ao procedimento).
    • 
    
  • $sp aponta para o topo da pilha.
    • 
    
  • A pilha cresce para baixo: dos endereços altos para os baixos. Para abrir espaço, subtrai do $sp. Para fechar, soma.
    • 
    
  • O movimento do $sp tem que ser balanceado (abriu 12, fecha 12), senão a pilha estoura.
    •

2.2Caminho de dados + unidade de controle (Aula 6)

  
O processador tem duas partes: o caminho de dados (por onde os dados passam: PC, memórias, registradores, ALU) e a unidade de controle (que liga e desliga cada peça conforme a instrução).

  
Fórmula
    
Tempo de execução = Nº de instruções × CPI × Ciclo de clock

    
Nº de instruções depende do compilador e da arquitetura. Ciclo de clock e CPI (ciclos por instrução) dependem do processador.

  

  
Subconjunto implementado: lw, sw (memória) · add, sub, and, or, slt (aritméticas e lógicas) · beq, j (fluxo).

  

    
Passos comuns a todas
1) PC envia o endereço → busca a instrução na memória.
2) Lê 1 ou 2 registradores usando os campos da instrução.
3) Usa a ALU: endereço (lw/sw), operação (aritméticas) ou comparação (desvios).

    
Passos específicos
Transferência: lê ou escreve na memória de dados.
Aritmética: escreve no registrador destino.
Desvio: muda o endereço da próxima instrução.

    
Elementos lógicos
Combinacionais: operam sobre dados; mesma entrada → mesma saída (ALU, mux). Sequenciais (de estado): guardam informação (memórias e registradores).

    
Clock
Decide quando um elemento de estado é atualizado (na borda de subida ou descida). Num ciclo: lê elementos de estado → passa pela lógica combinacional → escreve em elementos de estado. O banco de registradores é feito de flip-flops D, com decodificador na escrita e multiplexadores na leitura.

  • Quebra a instrução em passos; cada passo leva 1 ciclo e usa só uma unidade funcional (o trabalho fica balanceado).
    • 
    
  • Reaproveita peças: uma ALU só (calcula endereço e também incrementa o PC) e uma memória só (instruções e dados).
    • 
    
  • No fim de cada ciclo, guarda valores em registradores internos: IR (instrução), MDR (dado da memória), A, B e ALUOut. Mais muxes para compartilhar as peças. Resultado: hardware menor e mais barato.
    • 
    
  • PC, memória, registradores e IR precisam de sinal de escrita; a memória precisa de sinal de leitura. O PC pode receber PC+4, ALUOut ou o endereço do jump.
    • 
    
  • As instruções levam de 3 a 5 ciclos: lw = 5 · sw = 4 · tipo R = 4 · beq = 3 · j = 3.
    • 
  


  
O caminho de dados multiciclo (slides 37–39)

  
Compare com o monociclo: agora existe uma memória só e uma ALU só. Para isso funcionar, entre as peças aparecem registradores que seguram o resultado de um ciclo para o próximo, e muxes que escolhem quem usa cada peça em cada ciclo.

  

    
Registradores internos
IR: guarda a instrução buscada (a memória vai ser usada de novo para dados).
MDR: guarda o dado lido da memória.
A e B: guardam os dois registradores lidos.
ALUOut: guarda o resultado da ALU (endereço, conta ou alvo do desvio).

    
Muxes e sinais novos
IorD: o endereço da memória vem do PC (0, busca) ou da ALUOut (1, dado).
ALUSrcA: 1ª entrada da ALU é o PC (0) ou A (1).
ALUSrcB: 2ª entrada é B (00), 4 (01), imediato (10) ou imediato × 4 (11).
PCSource: novo PC vem da ALU (00), da ALUOut (01) ou do jump (10).
IRWrite, PCWrite, PCWriteCond: quando escrever no IR e no PC.

    Exceções e interrupções no multiciclo (slides 66–71)
    
  
    
    
    Diferença
    Exceção: evento inesperado de dentro do processador (overflow, instrução indefinida, chamada ao SO). Interrupção: evento de fora, vindo de dispositivos de E/S. Mau funcionamento do hardware pode ser os dois.
    
    
    O que o hardware faz
    1) salva o endereço da instrução no EPC; 2) registra a Causa (bit 0 = instrução indefinida, 1 = overflow); 3) transfere o controle para o SO, no endereço C000 0000hex. Com interrupções vetoradas: indefinida → C000 0000, overflow → C000 0020. Na FSM entram os estados 10 (indefinida) e 11 (overflow, detectado no estado 7).
    
  
    

  
    2.5Pipeline: a lavanderia
    
  
    Pipeline é uma técnica que sobrepõe no tempo as fases de várias instruções. A analogia do slide: lavar → secar → dobrar → guardar. Assim que a 1ª carga sai da lavadora, a 2ª já entra.
    
  
    
    
    Lavanderia: sem pipeline × com pipeline
      
    
    
    
      
    LavarSecarDobrarGuardar
    
      
    
      
    
    
    
  
    
  
    Paradoxo do pipeline
    O tempo de cada instrução sozinha não diminui. O ganho vem de colocar todos os recursos trabalhando em paralelo. O pipeline melhora o throughput (instruções por unidade de tempo), não o tempo de uma instrução.

    Nos slides em inglês: IF, ID, EX, MEM, WB. Na representação estilizada: MI (memória de instruções), Reg, ALU, MD (memória de dados), Reg.
    

  
    Quanto o pipeline ganha?
    
  
      
    
    • Ideal: ganho = número de estágios. Pipeline de 5 estágios = 5 vezes mais rápido.
      • 
    
    • Se os estágios forem perfeitamente balanceados: Tempo entre instruções (pipeline) = Tempo entre instruções (sem pipeline) / Nº de estágios.
      • 
    
    • Na prática ganha menos: estágios não balanceados e o tempo para encher o pipeline.
      • 
    
    • No MIPS: monociclo = 8 ns por instrução; estágio mais lento (memória, ALU) = 2 ns. Ideal seria 8/5 = 1,6 ns, mas o estágio tem que ser de 2 ns. Então o ganho máximo é 8/2 = 4, não 5.
      • 
  
    
  
    Exemplo do slide 6: três lw
    
  
    
    
    lw $t1, 100($t0)
lw $t2, 200($t0)
lw $t3, 300($t0)
    
    
    Monociclo: 3 × 8 = 24 ns
    Pipeline: a 1ª termina em 5 × 2 = 10 ns; cada uma das outras sai 2 ns depois → 10 + 2 + 2 = 14 ns
    Ganho: 24 / 14 ≈ 1,7
    Com mais 1000 instruções: (1003 × 8) / (14 + 1000 × 2) = 8024 / 2014 ≈ 4

    O MIPS foi feito pensando no pipeline (slide 8)
    
  
    
    
    Facilita
    Todas as instruções têm o mesmo tamanho · poucos formatos · operandos de memória só no lw e sw · operandos alinhados na memória.
    
    
    Atrapalha (conflitos)
    Estruturais: duas instruções querem o mesmo hardware (ex.: acesso simultâneo à memória) → replicar hardware. Controle: decidir algo com base numa instrução que ainda não terminou (desvios). Dados: precisar de um resultado que ainda está no pipeline.
    
  
    

  
    Registradores de pipeline: os "cestos de roupa"
    
  
    Entre um estágio e o próximo existe um registrador que guarda tudo o que a instrução vai precisar adiante: BI/DI, DI/EX, EX/MEM e MEM/ER (o nome é dos dois estágios que ele separa). Na lavanderia, é o cesto entre a lavadora e a secadora.
    
  
      
    
    • Para passar algo de um estágio para outro mais adiante, tem que guardar no registrador de pipeline, senão a próxima instrução apaga.
      • 
    
    • Cada peça do caminho de dados só pode ser usada em um estágio, senão vira conflito estrutural.
      • 
    
    • Não existe registrador de pipeline depois do ER.
      • 
    
    • Instruções e dados andam da esquerda para a direita, exceto a escrita no banco de registradores e o cálculo do PC, que voltam e afetam instruções seguintes.
      • 
    
    • Correção do slide 22: no lw, o número do registrador destino tem que viajar por DI/EX, EX/MEM e MEM/ER até o ER; senão, a instrução seguinte destruiria esse valor.

    2.6Conflitos (hazards): quando o pipeline engasga
    
  
    
    
    Estrutural
    Duas instruções querem a mesma peça ao mesmo tempo. Na lavanderia: uma máquina que lava e seca e está ocupada. Solução: replicar hardware (memórias separadas).
    
    
    De dados
    Uma instrução precisa de um resultado que ainda não ficou pronto. Soluções: bolhas, adiantamento e reordenar o código.
    
    
    De controle
    Num desvio, o processador ainda não sabe para onde ir e outras instruções já entraram. Soluções: parar, predição, desvio retardado, antecipar a decisão.
    
  
    

  
    Conflito de dados
    
  
    
    
    add $s0, $t0, $t1   # escreve $s0 só no ER (ciclo 5)
sub $t2, $s0, $t3   # quer ler $s0 no DI (ciclo 3)!
    
    
    Sem fazer nada, o sub leria o valor velho de $s0. Parando o pipeline, seriam necessárias 2 bolhas.
    
    
    Soluções: pelo compilador (inserir nops ou reordenar; só com nops ficaria lento, porque o conflito é muito frequente) ou por adiantamento (bypass / forwarding): pegar o resultado direto na saída da ALU, por um atalho interno, sem esperar ele ser escrito.
    
  
    
  
    Regra de validade do adiantamento
    Só dá para adiantar se o estágio onde a próxima instrução precisa do dado vier depois (no tempo) do estágio onde a instrução atual produz o dado.
    
  
    add → sub: a ALU do add produz no fim do ciclo 3, o sub usa no ciclo 4. Válido.
    
  lw → sub: o lw só tem o dado no fim do MEM (ciclo 4), mas o sub precisaria no ciclo 4. Inválido: tem que pôr 1 bolha e aí adiantar.

      Condição de parada

      Conflito de controle (desvios)
      
  
      No slide 9, o beq faz o lw seguinte esperar: entra uma bolha (parada) de 2 ns.
      
  
      
  
      Quanto maior o pipeline, maior a perda em cada parada. Parar sempre custa caro. Por isso existe a predição de desvios:
      
  
      
    
      Predição simples
      "Chuta" que o desvio não vai acontecer. Acertou: pipeline a toda velocidade. Errou: descarta as instruções erradas e busca no endereço certo.
      
    
      Predição mais sofisticada
      Prevê que alguns desvios acontecem e outros não. Ex.: o desvio do fim de um laço quase sempre volta.
      
    
      Predição dinâmica (em hardware)
      Guarda um histórico de cada desvio (realizado ou não) para prever o futuro. Acerta cerca de 90%. Usa um buffer indexado pelos bits de baixo do endereço da instrução de desvio.
      
    
      Desvio retardado (delayed branch)
      A instrução logo depois do desvio sempre executa (o "slot"). O compilador coloca lá algo útil que não afeta o desvio. Consegue preencher cerca de 50% dos slots.
      
  
      
  
      Se a predição errar, é preciso eliminar o efeito das instruções executadas por engano e voltar ao endereço correto. Pipeline com muitos estágios = custo alto para cada erro.
      

  
      Descarte (flush) e antecipação do desvio (slides 41–46)
      
  
      Se o desvio só é decidido no MEM, três instruções já entraram (BI, DI e EX) e precisam ser descartadas. A melhoria é antecipar a decisão para o DI (mover o somador do alvo e um comparador "=" para lá): aí só a instrução que está sendo buscada no BI é descartada (sinal Elimina.BI / IF.Flush, que zera o campo de instrução do BI/DI).
      
  
      
  
      
  
      
  
      Endereço alvo do slide: 40 beq $1, $3, 7 → (40 + 4) + 7 × 4 = 72, onde está o lw $4, 50($7). Predizer "não desvia" reduz pela metade o custo, se metade dos desvios não acontece.
      

  
      Preditor de 2 bits (slides 47–48)
      
  
      Com 1 bit ("o que aconteceu da última vez"), um laço erra 2 vezes: na primeira e na última volta. O de 2 bits só muda de ideia depois de errar duas vezes seguidas.

      2.7Exceções no pipeline (slides 50–53)
      
  
      Exemplo: add $1, $2, $1 gera overflow. É tratado como um conflito de controle: o controle vai para a rotina de tratamento no endereço 4000 0040hex.
      
  
      
    
      Ações do hardware
      Elimina as instruções seguintes ao add: Elimina.BI (zera a instrução no BI/DI), Elimina.DI e Elimina.EX (zeram os sinais de controle desses estágios). Coloca 4000 0040hex no PC por um mux. Para a instrução culpada no meio, deixa as anteriores terminarem, carrega o registrador de Causa e salva o endereço no EPC.
      
    
      Causas e o SO
      a) pedido de E/S; b) serviço do SO pedido pelo programa; c) instrução não definida; d) mau funcionamento do hardware; e) overflow. Se várias acontecem no mesmo ciclo, há prioridade. O MIPS tem exceções precisas. O SO: nos casos c, d, e termina o programa com erro; nos casos a, b salva o estado, faz o serviço e continua.

      3.3Potência: um laço dentro do outro
      
  
      Ideia: 2⁵ = 2 × 2 × 2 × 2 × 2. Potência é multiplicar várias vezes, e multiplicar é somar várias vezes. Então são dois laços, um dentro do outro:
      
  
      
    
      Laço de fora (externo)
      Roda expoente vezes. Cada volta faz: resultado = resultado × base.
      
      
      Laço de dentro (interno)
      Roda base vezes. Cada volta faz: acumulador = acumulador + resultado. No fim, acumulador = resultado × base.
      
    
      Por que o resultado começa em 1?
      Porque 1 é o "neutro" da multiplicação: 1 × 2 × 2 × 2 = 8. E de brinde, se o expoente for 0, o laço de fora não roda e o resultado fica 1 (x⁰ = 1). Começar com o valor da base (como muita gente faz) quebra quando o expoente é 0.
      
  
      
  
      
    
      C
      res = 1;
for (i = 0; i != exp; i++) {
    acc = 0;
    for (j = 0; j != base; j++)
        acc = acc + res;   /* acc = res × base */
    res = acc;
}
/* base=$s0 exp=$s1 res=$v0
   i=$t0 acc=$t1 j=$t2 */
      
    
      MIPS
      # POTÊNCIA: $v0 = $s0 ^ $s1   (base ^ expoente)
        addi $v0, $zero, 1       # resultado = 1
        add  $t0, $zero, $zero   # i = 0 (multiplicações feitas)
externo:
        beq  $t0, $s1, fim       # i == expoente? acabou
        add  $t1, $zero, $zero   # acumulador = 0
        add  $t2, $zero, $zero   # j = 0
interno:
        beq  $t2, $s0, fim_mult  # j == base? terminou a multiplicação
        add  $t1, $t1, $v0       # acumulador += resultado
        addi $t2, $t2, 1         # j++
        j    interno
fim_mult:
        add  $v0, $t1, $zero     # resultado = resultado × base
        addi $t0, $t0, 1         # i++
        j    externo
fim:

      3.4Raiz quadrada: dois jeitos
      
  
      Jeito 1: subtrair ímpares (o mais curto)
      
  
      Todo quadrado perfeito é uma soma de ímpares seguidos: 1 = 1 · 4 = 1+3 · 9 = 1+3+5 · 16 = 1+3+5+7. Olhe o desenho: cada quadrado é o anterior mais uma "camada em L", e cada camada tem um número ímpar de quadradinhos.
      
  
      
  
      Então, para achar a raiz de N: vá tirando 1, 3, 5, 7… de N enquanto der. O número de vezes que deu para tirar é a raiz (inteira).
      
  
      
    
      C
      raiz = 0; sobra = n; impar = 1;
while (!(sobra < impar)) {
    sobra = sobra - impar;
    impar = impar + 2;
    raiz  = raiz + 1;
}
/* n=$s0 raiz=$v0 impar=$t0 sobra=$t2 */
      
    
      MIPS
      # RAIZ QUADRADA (ímpares): $v0 = raiz inteira de $s0
        add  $v0, $zero, $zero   # raiz = 0
        add  $t2, $s0, $zero     # sobra = n (cópia, não estraga $s0)
        addi $t0, $zero, 1       # ímpar = 1
loop:   slt  $t1, $t2, $t0       # $t1 = 1 se sobra < ímpar
        bne  $t1, $zero, fim     # não dá para tirar? acabou
        sub  $t2, $t2, $t0       # sobra = sobra - ímpar
        addi $t0, $t0, 2         # próximo ímpar: 1, 3, 5, 7...
        addi $v0, $v0, 1         # raiz = raiz + 1
        j    loop
fim:                             # em $t2 sobra o resto (n - raiz²)

Q:      beq  $t2, $t0, Cubo
        add  $t1, $t1, $t0
        addi $t2, $t2, 1
        j    Q
Cubo:   add  $t3, $zero, $zero   # cubo = quadrado × i
        add  $t2, $zero, $zero
C:      beq  $t2, $t0, Testa
        add  $t3, $t3, $t1
        addi $t2, $t2, 1
        j    C
Testa:  slt  $t4, $s0, $t3       # n < i³ ?
        bne  $t4, $zero, Achou
        addi $t0, $t0, 1
        j    Tenta
Achou:  addi $v0, $t0, -1
      
    
      Para 30: 1, 8, 27 cabem; 64 passa → 3.
      
  
      
  
      5. Divisão inteira $s0 ÷ $s1: quociente em $v0 e resto em $v1, só com subtração.
      
    
              add  $v0, $zero, $zero   # quociente = 0
        add  $v1, $s0, $zero     # resto = a
Div:    slt  $t0, $v1, $s1       # resto < b ?
        bne  $t0, $zero, Fim     # sim: acabou
        sub  $v1, $v1, $s1       # resto = resto - b
        addi $v0, $v0, 1         # quociente++
        j    Div
Fim:
      
    
      17 ÷ 5: 17 → 12 → 7 → 2. Três subtrações: quociente 3, resto 2.
      
  
      

  
      3.8Erros que mais derrubam nota
      
  
      
    
      Esquecer de zerar o acumulador
      Registrador não começa em zero "sozinho" no meio de um programa. Sempre add $t1, $zero, $zero antes de somar.
      
    
      Esquecer o j de volta
      Sem o j loop no fim do corpo, o laço roda uma vez só. Sem incrementar o contador, roda para sempre.
      
    
      Zerar o acumulador fora do laço de dentro
      Na potência, o acumulador e o j têm que ser zerados a cada volta do laço de fora.
      
    
      Trocar a ordem do sub ou do slt
      sub $t0, $a, $b é a − b. slt $t0, $a, $b pergunta "a < b?". Leia sempre da esquerda para a direita, destino primeiro.
      
    
      Usar constante onde precisa de registrador
      add $t0, $t0, 1 está errado: com constante é addi. E beq $t0, 5, L não existe: coloque o 5 num registrador antes.
      
    
      Deslocamento de memória errado
      Palavra = 4 bytes. A[3] é 12($s3), não 3($s3). Endereço de palavra tem que ser múltiplo de 4.
      
    
      Confiar num $t depois de jal
      O procedimento pode estragar $t, $a e $v. Se precisa do valor depois, salve na pilha ou use $s (e quem usa $s salva antes).
      
    
      Escrever em $zero
      add $zero, $t0, $t1 não dá erro, mas o resultado some: $zero é sempre 0.

      Edite à vontade. Clique no número de uma linha para pôr um breakpoint (bolinha vermelha).

      Passo roda uma linha; Voltar desfaz a última; Animar roda sozinho; Executar vai até o fim ou até um breakpoint. Atalho: Ctrl+Enter = Passo.
      
    
      3. Observe
      Registrador que muda pisca. A pilha mostra quem foi salvo em cada endereço. A memória mostra seus dados do .data.
